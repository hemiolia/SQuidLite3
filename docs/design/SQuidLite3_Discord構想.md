# SQuidLite3 × Discord 構想（0.1・2026-10-05 Opus 5.5）

前田さんの依頼（原文は開発ログ）: 将来の展開として Discord の bot でいろんな機能を展開したい。どんなことができれば便利で面白いか考えておく。

## 前提にする原則

1. **ローカルファーストを崩さない。** 記録の取得と計算は利用者の端末（または利用者の NAS）で行う。Discord に出すのは、利用者が出すと決めた要約だけ。
2. **任天堂への問い合わせを増やさない。** bot は、アプリがすでに保存した記録だけを使う。bot のために任天堂へ追加で取りに行かない。
3. **他人の名前を勝手に出さない。** 試合の記録には味方や相手の名前が入っている。初期設定では自分以外の名前を出さない。仲間どうしで共有に同意した人だけ名前を出す。
4. **初心者でも設定できる。** 最初の段は、Discord の「ウェブフック」の URL をアプリに貼るだけで動くようにする（bot の登録や鍵の管理を利用者にさせない）。
5. **NOAHS の方針。** bot の投稿も製品の画面の一部として扱い、絵文字を使わず、文字と形で意味が伝わるようにする。

## できると便利・面白いこと

### A. 自分の記録が流れてくる（受け身で楽しい）

- **まとまりの要約**: 遊び終わって30分たったら「オープン 12戦 8勝4敗、パワー +86、最長連勝5、いちばん活躍した試合」を1枚のカードで投稿。パワーの推移グラフ画像つき。毎試合流すより騒がしくない。
- **自己ベストの更新**: Xパワーの最高値、1試合のキル数・塗り、バイトの納品数・最高評価、オカシラ討伐などを更新したときだけ知らせる。
- **バイトのシフト要約**: 評価の上下、WAVE ごとの結果、ビッグランやバイトチームコンテストの記録更新。

### B. Discord から聞く・操作する（便利）

- **/戦績** 期間・モード・ルールを選ぶと、勝敗・勝率・キル/デス・ブキ別の成績を返す。
- **/推移** Xマッチのエリアの30日間、などを選ぶとグラフ画像を返す。
- **/ステージ** ステージ×ルールの自分の勝率表。苦手な組み合わせが一目で分かる。
- **/直近** 最後の試合の詳細（両チームのブキ構成、表彰）。
- **Discord からタグを付ける**: まとまりの要約カードに「対抗戦」「練習」「エンジョイ」「ガチ」「下げラン」のボタンを付け、押すだけでその回の試合にタグが付く。アプリを開かずに事後のタグ付けが終わる（画面設計 0.1 の「まとまりでタグを付ける」を Discord でも）。

### C. 予定と組み合わせる（先回り）

- **ローテーションの予告と自分の相性**: 「次の Xマッチはガチホコ。あなたのホコの勝率 58%。得意なステージ（勝率 70%）が入っています」。アプリはステージの予定をすでに取得している。
- **フェス・ビッグラン・バイトチームコンテストの開催通知**と、その種類での自分の過去の記録。

### D. 仲間と（共有に同意した人どうし）

- **対抗戦（プラベ）の戦績表**: 同じプラベを仲間の何人かが記録していれば、試合の ID で重ね合わせて、チームごとの対戦成績、メンバーごとの成績、ブキ構成ごとの勝率を出す。プラベの事後分析はほかの道具にほとんど無く、SQuidLite3 の独自の価値になる。
- **身内のリーグ**: 月ごとの勝率、Xパワーの最高、キル数、納品数の表と、その月の称号。参加は一人ずつ選べて、いつでも抜けられる。
- **一緒に遊んだ記録**: 「今週 ○○ さんと組んだ試合 23戦15勝」（両方が共有に同意している場合だけ）。

### E. 面白さを足す

- **称号（実績）**: 「同じステージで10連勝」「ノックアウト勝ち30回」「全ブキ種で勝利」など、記録を全部持っているからこそ作れる称号を bot が授与する。
- **今日の名場面**: 夜に一回、その日の最多キルの試合や、カウントの劣勢から逆転した試合を選んで紹介する。
- **リプレイコードの共有**: 保存してあるリプレイを、カードにして仲間に見せる。
- **シーズンのまとめ**: シーズンの終わりに「いちばん使ったブキ、いちばん勝ったステージ、総塗り面積、相棒」を1枚の画像に。共有したくなる仕掛け。

## 仕組みの段階

1. **段1 ウェブフック（一方通行）**: 利用者がチャンネルのウェブフック URL をアプリの設定に貼るだけ。A と、C の通知、E の名場面・まとめが作れる。サーバーも bot の登録も要らない。導入案内に一段足す。
2. **段2 応答する bot（B のコマンドとボタン）**: ボタンやコマンドに答えるには bot が要る。二つの作り方があり、どちらにするかは前田さんの判断事項。
   - 公式 bot を一つ運営し、利用者のアプリが外向きに接続して中継してもらう方式。利用者は「bot を招待してアプリでつなぐ」だけで済む。ただし中継サーバーの運営（費用・障害対応・利用者データが一時的に通る責任）が要る。
   - 利用者や仲間内の管理者が自分の bot を NAS や PC で動かす方式。Discord への接続は外向きだけでよく、家のネットワークを外に開かなくて済む。ただし bot の登録が要り、初心者には重い。
3. **段3 仲間の機能（D）**: 共有の同意と取り消し、名前の出し方の設定が先に要る。段2の方式の上に作る。

## 前田さんに決めてもらうこと

- 段2の作り方（公式 bot を中継方式で運営するか、自分で動かす方式にするか）。
- 他のプレイヤーの名前をどこまで出してよいか（初期設定は自分だけ）。
- bot の投稿でも絵文字を使わない方針でよいか（NOAHS の方針をそのまま当てる案）。
