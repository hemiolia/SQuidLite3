# SQuidLite3 製品形態（設計 0.1・2026-10-05 Opus 5.5）

名称は SQuidLite3 とする（前田さん 2026-10-05 指示。「イカリング3」は商標上の懸念があるため名称に入れない）。データの置き場所の名称（NAS `~/ikaring-archive`、Drive `イカリング3アーカイブ`）の変更はデータの移動にあたるため、前田さんの明示があるまで変えない。

## 一番の目的

パソコンに明るくない人でも、データを自由自在に使えること（前田さん 2026-10-05）。UI は NOAHS の方針に従う（同日）。NOAHS 側の規則は `NOAHS由来UI方針_抜粋.md` に出典つきで集める。

## 形式の判断：自分の機械で動く Web アプリ（PWA）

一つの Web 画面を、PC のブラウザでもスマホのブラウザでも使う。ホーム画面に追加すればアプリのように開ける（PWA）。ストア配布のネイティブアプリは当面作らない。

理由:

1. 収集処理は常時動く機械（前田さんは NAS、他の人は自分の PC）に置くしかない。任天堂の認証情報をこちらのサーバーで預かる集中型サービスは、他人の認証情報を預かる責任と、非公式 API に依存する事業リスクが大きいので採らない。
2. 画面を収集機械が配信すれば、DB の写しを手元に置かずに済み、タグ付けなどの書き込みも正本へ直接届く。Google Drive との双方向同期は、書き込み元が二つになり競合と取り違えが起きるので採らない。Drive は読み取り用の配信先にとどめる。
3. App Store / Google Play の審査と更新の手間を負わず、同じ画面を PC とスマホで共有できる。

## 前田さんの環境

- NAS で収集と画面配信を行う。外からは Cloudflare Tunnel 経由で HTTPS 公開し、Cloudflare Access（メールのワンタイムコード等）で本人だけに絞る。NOAHS の `gnzm.jp` と同じ仕組みで動く。
- そのためにホスト名が要る。現ゼミの `gnzm.jp` は別団体の領域なので混ぜない。SQuidLite3 専用のドメインを推奨する（公開リポジトリの案内ページにも使える）。
- 公開までのつなぎとして、Mac のループバック画面 `scripts/desktop_app.py`（NAS の正本へ SSH で読み書き）を `Start.command` のダブルクリックで開けるようにする。

## ほかの人の環境（公開配布）

- 自分の PC に入れ、ダブルクリックで起動する。収集と画面配信はその PC で動く。同じ家のスマホからは PC の画面を開ける。外から使いたい人だけ、後で Tunnel 等を足す。
- 導入は対話型の案内で行う（前田さんの rclone 型の提案）。番号を選んで進む端末の対話画面を先に作り、同じ手順をブラウザの初回案内画面にも載せる。手順：前提の確認 → 保存先 → 任天堂の認証 → 初回収集 → 自動収集の登録 → 画面を開く。
- 今は Python と Node.js の導入が前提で、初心者には重い。最終的には単体で動く配布物（Python と Node を同梱）にする。
