# SQuidLite3 導入案内（設計 0.1・2026-10-05 Opus 5.5）

前田さんの指示（2026-10-05、要点）: アプリとしてのリリースはまだでも、パソコン初心者でも導入できる導線設計を早めに考える。rclone のような対話型インターフェースを用意するのが良心的。みんなが AI エージェントを駆使しているわけではない。

過去の指示（2026-09-22）: パソコン操作が苦手な人、ターミナルが何かすら知らない人でも簡単に導入できるようにする。GitHub からディレクトリごとダウンロードしたらすぐに認証して使えるようにするのが理想。

UI の方針は NOAHS に従う（`NOAHS由来UI方針_抜粋.md`）。とくに、文言は専門語ではなく「何が起こるか」を表す平易な行動表現で書く（6.8）、予想しづらいが行動を助ける情報を優先して書く（6.8）、無反応の凍結状態を見せない（6.10）、絵文字を使わない（6.7）。

## 形

1. 配布物の中の「SQuidLite3 を始める」（macOS は `.command`、Windows は `.bat`）をダブルクリックすると、黒い画面（ターミナル）が開き、案内が始まる。
2. 案内は番号を選んで Enter を押すだけで進む。選択肢には必ず「おすすめ」を一つ付け、何も入力せず Enter を押すとおすすめが選ばれる。
3. 各段の冒頭に「いま何段目か／全部で何段か」と「この段で何が起こるか」を一行で出す。
4. 時間がかかる処理（依存の導入、初回の取得）は、進んでいることが分かる表示を出し続ける。黙って止まったように見せない。
5. 途中でやめても、次に起動すれば終わった段の続きから再開する（状態を設定ファイルに記録）。
6. 失敗したら、原因を平易に一行で示し、「もう一度試す」「やり方を見る」「やめる」の番号を出す。英語のエラー文をそのまま投げない（詳細はログファイルに残し、その場所を示す）。

## 段

| 段 | 画面で聞くこと・すること | 備考 |
| --- | --- | --- |
| 1 前提の確認 | Python と Node.js があるか自動で調べる。無ければ「入れ方を開く（おすすめ）」で公式の入手ページを開き、入れ終わったら Enter で再確認。 | 将来は同梱配布物にしてこの段を無くす（残タスク C7）。 |
| 2 保存先 | 「この PC に保存する（おすすめ）」「NAS など別の機械に保存する（詳しい人向け）」。前者は保存先フォルダを表示し、変えたい人だけ入力。 | 後者は現行の NAS マーカー方式。 |
| 3 任天堂の認証 | 「ブラウザで任天堂のログイン画面を開きます」と説明してから開く。ログイン後に出るリンクの貼り方を、操作の順に番号つきで示す。パスワードはこの画面に入れないことを明記する。 | 既存の nxapi の認証を使う。 |
| 4 最初の取得 | 「いまから記録を取りに行きます。数分から数十分かかります」と出し、取得した試合数を数えながら表示する。 | 既存の sync。 |
| 5 自動取得 | 「PC が起動している間、2分ごとに新しい記録を取りに行く（おすすめ）」「自分で起動したときだけ」。 | macOS は LaunchAgent、Windows はタスクスケジューラ。 |
| 6 画面を開く | 「記録を見る画面を開きます」。ブラウザで記録の画面を開き、スマホから同じ画面を開く方法（同じ Wi-Fi のとき）を示す。 | 既存の desktop_app を土台にする。 |
| 7 Google Drive（任意） | 「AI（ChatGPT など）から記録を読めるように Google Drive にも置く」「置かない（おすすめ）」。 | 使う人だけ rclone の認証へ案内する。 |

## 二回目以降

ダブルクリックすると「記録を見る画面を開く（おすすめ）」「設定を変える」「認証をやり直す」「取得の状況を見る」の番号メニューになる。rclone config のメニューと同じく、何をしたいかを選ぶだけで済む。

## 実装の順

1. 端末の対話案内（Python 標準ライブラリのみ。macOS / Windows / Linux で同じ文言）。
2. 同じ段と文言を、ブラウザの初回案内画面にも載せる（段と文言の定義を一か所に置き、両方から使う）。
3. 同梱配布物（Python と Node を同梱し、段 1 を無くす）。
